# Threat model

Scope: the gateway (`gateway/`), its admin page (`admin-ui/`), its data at rest (SQLite file,
`audit.jsonl`), and its connection to the inference server (Ollama or an OpenAI-compatible server).
Out of scope: the host OS, the inference server's own security, network perimeter and TLS
termination, and the browser demo (which has no server and no data of its own). The Helm chart's
NetworkPolicy and pod hardening reduce the cluster attack surface but were validated by rendering in
tests, not on a live cluster ([kubernetes.md](kubernetes.md)).

Every control below points at code and at the test that exercises it. "Residual risk" is what is left
after the control; items marked **roadmap** are not implemented. Related: [controls mapping](controls.md),
[compliance notes](compliance.md), [ADRs](adr/README.md).

## System and trust boundaries

```
 Applications ──(bearer key)──►┐
 Admin page (browser) ─(admin key)─►  Gateway (FastAPI, one process)  ──HTTP──►  Inference server
 Prometheus ──(optional token)──►┘     │            │                              (Ollama / vLLM / ...)
                                       ▼            ▼
                              SQLite (keys, usage,   audit.jsonl (hash chain) ──► WORM archive
                              documents, vectors)                                  (operator procedure)
```

| Boundary | What crosses it | Default exposure |
|---|---|---|
| Client → gateway | Prompts, documents, questions, API keys or OIDC access tokens | `127.0.0.1:8080`; remote access through a reverse proxy with TLS (documented, not built in). On Kubernetes: ClusterIP plus a default-deny NetworkPolicy admitting only configured peers (`deploy/helm/local-llm-gateway`, `test_helm_chart.py::test_default_render_is_a_hardened_single_replica_gateway`) |
| Gateway → identity provider | JWKS and discovery fetches (public keys only), when OIDC is enabled | https required unless `GATEWAY_OIDC_ALLOW_HTTP=true` |
| Gateway → inference server | Prompts and retrieved passages; upstream API key if set | `127.0.0.1:11434` (Ollama) or `OPENAI_COMPAT_BASE_URL` |
| Gateway → disk | Keys, usage, documents, vectors, audit entries | Files under `GATEWAY_DB_PATH`, `GATEWAY_LOG_DIR` |
| Scraper → `/metrics` | Counters labelled by route, status, key **label**, model | Open unless `GATEWAY_METRICS_TOKEN` is set |

Assets: documents and prompts (may contain PHI/PII), API keys, the audit trail, availability of a
shared model.

## STRIDE

| Threat | Example | Control | Test | Residual risk |
|---|---|---|---|---|
| **S**poofing an application | Calling the API without a key, with a guessed or revoked key | Bearer credential required on every `/v1` and `/admin` route; keys are 256-bit random (`secrets.token_urlsafe(32)`); revoked keys rejected (`auth.require_key`, `store.get_active_key`) | `test_gateway.py::test_requires_bearer_key`, `::test_revoked_key_is_rejected`; `test_demo_engine.py::test_keys_rate_limit_and_revocation_use_the_real_auth_code` | API keys identify applications and don't expire; a leaked key works until revoked |
| Spoofing a person (OIDC) | Forged, tampered, expired or replayed-elsewhere tokens; `alg: none`; HMAC-with-public-key confusion | Signature checked against the issuer's JWKS; allow-list RS256/ES256 checked before key lookup; key type must match the algorithm; `iss`, `aud`, `exp`, `sub` required; skew-bounded `exp`/`nbf`; 16 KiB size cap (ADR 0005, `gateway/identity.py::verify_token`) | `test_identity.py::test_algorithm_allow_list_blocks_none_hmac_confusion_and_other_algs`, `::test_forged_and_tampered_tokens_are_rejected`, `::test_expiry_not_before_and_clock_skew`, `::test_audience_issuer_and_required_claims` | A stolen, unexpired token works until it expires (no introspection or revocation list); MFA and session policy are the IdP's job; the IdP and its signing keys are trusted |
| Spoofing via the key source | A rogue JWKS or discovery document | https-only key URLs (unless explicitly allowed); discovery document's `issuer` must equal the configured issuer | `test_identity.py::test_discovery_must_name_the_configured_issuer`, `::test_unsafe_oidc_settings_fail_at_startup` | DNS/TLS compromise of the IdP host is out of scope |
| Spoofing an admin | A normal key or a non-admin user calling admin routes | `require_admin` on key, document, ACL, user and pull routes; roles from IdP groups via an explicit map; a token with no mapped group gets 403 | `test_gateway.py::test_non_admin_cannot_manage_keys`; `test_documents.py::test_only_admins_add_or_remove_documents`; `test_identity.py::test_admin_api_respects_roles_and_audits_the_user`, `::test_valid_token_without_a_mapped_group_is_forbidden` | Group membership is whatever the IdP asserts; a mis-mapped group grants its roles. No SCIM sync (**roadmap**) |
| **T**ampering with the audit trail | Editing or deleting a line in `audit.jsonl` | SHA-256 hash chain; `GET /admin/audit/verify` returns the first bad line (ADR 0003) | `test_gateway.py::test_audit_verify_detects_tampering`; `test_demo_engine.py::test_tampering_is_detected_and_the_tail_limitation_is_reported` | The newest entries can be rewritten with recomputed hashes undetected until compared with a WORM archive; no signed checkpoints (**roadmap**) |
| Tampering with stored passages | Editing or swapping encrypted passages in the SQLite file | AES-GCM authentication with associated data naming document, passage and field; decryption failure fails closed | `test_encryption.py::test_ciphertexts_are_bound_to_their_row_and_key` | Only when encryption is on; plaintext deployments don't detect direct edits |
| Tampering with documents | Replacing a policy so answers change, or widening its access list | Only admins add/remove documents and change access lists; `document_added` (with its ACL), `document_removed`, `document_acl_changed` and `collection_acl_changed` (before/after) audited with the actor | `test_documents.py::test_only_admins_add_or_remove_documents` | Anyone with write access to the SQLite file can edit passages directly; not detected (**roadmap**: content hashes in the audit entry) |
| Tampering with models | A swapped, re-pulled or malicious model | Pulls admin-only and audited; pinned digests in a lock file verified against what the backend serves (Ollama manifest digest, or SHA-256 of weight files) at startup, after pulls, on demand and every interval; `enforce` refuses unpinned or mismatched models (ADR 0008) | `test_supply_chain.py::test_enforce_serves_only_pinned_models_whose_digest_matches`, `::test_digests_are_rechecked_after_the_interval_and_after_pulls`, `::test_openai_compatible_models_are_verified_by_hashing_pinned_weight_files` | Digests prove integrity against *your* pin, not provenance (no signature verification, **roadmap**); pins are trust on first use; weight files are re-hashed only at startup, after pulls and on demand |
| **R**epudiation | "We never created that key / asked that question" | Key creation/revocation, document changes and every document question are logged with the key label; prompts optionally | `test_gateway.py::test_audit_log_records_admin_actions_and_redacted_prompts`; `test_documents.py::test_questions_are_audited_with_sources_and_redaction` | Key callers are attributed to a key label; token callers to `user:<username>` (`test_identity.py::test_admin_api_respects_roles_and_audits_the_user`). Plain chat completions are only logged when `GATEWAY_LOG_PROMPTS=true` |
| **I**nformation disclosure: logs | PHI/PII copied into the audit log | Prompt logging is off by default; `GATEWAY_REDACT_PROMPTS` masks SSNs, Luhn-valid cards, DOBs, emails, US phones; full keys never logged | `test_gateway.py::test_audit_log_records_admin_actions_and_redacted_prompts`; `test_redact.py` | Pattern-based, not a DLP: names, addresses, MRNs and free-text PHI are not redacted |
| Information disclosure: data at rest | Copy of `gateway.db`, a backup, or `audit.jsonl` | Envelope encryption (AES-256-GCM, per-document data keys wrapped by a rotatable KEK) of passages and vectors; optional sealing of audit free-text fields; keys never in backups; restore checks key availability (ADR 0007, `gateway/crypto.py`) | `test_encryption.py::test_passages_and_vectors_are_sealed_on_disk_and_readable_through_the_api`, `::test_audit_text_fields_are_sealed_and_the_chain_verifies_without_keys`; `test_backup_restore.py::test_backup_restore_drill_brings_back_documents_keys_acls_and_the_audit_chain` | Off by default. **API keys are stored in plaintext**; titles, ACLs and sizes are readable; a keyring stored next to the database or backups defeats the encryption; backups taken before enabling it keep plaintext. Only a local keyring ships (KMS is **roadmap**); use full-disk encryption as well |
| Information disclosure: telemetry | Prompts leaking into metrics or traces | Metric labels are route templates, status, key **label** and model; spans carry only GenAI attributes, never prompt or completion text | `test_metrics.py::test_requests_are_counted_by_route_template_and_key_name`; `test_telemetry.py::test_chat_emits_genai_span` | Key labels and model names are visible to whoever can scrape `/metrics`; set `GATEWAY_METRICS_TOKEN`. Token callers are labelled `oidc`, never by user name (`test_identity.py::test_token_users_are_metered_without_user_names_in_metrics`) |
| Information disclosure: upstream | Client keys forwarded to the model server | Upstream gets only `OPENAI_COMPAT_API_KEY`, never the caller's key | `test_backends.py::test_openai_compatible_chat_keeps_gateway_contract`, `::test_no_upstream_key_means_no_authorization_header` | Traffic to a remote inference server is plain HTTP unless the URL is `https://` |
| **D**enial of service | One app floods the shared model | Per-key and per-token-subject sliding-window rate limit (429); upload size limit (413); `top_k` capped at 12; embeddings capped at 256 inputs; JWKS refetch on unknown `kid` at most every 30 s | `test_gateway.py::test_rate_limit`; `test_identity.py::test_rate_limit_applies_per_token_subject`, `::test_jwks_cache_key_rotation_and_unknown_kid_throttling`; `test_documents.py::test_input_validation`; `test_metrics.py::test_rejections_show_up_by_status_with_key_name` | Limit is per process and in memory; no token quotas or `max_tokens` cap; no request-body cap on chat; PDF parsing of hostile files bounded only by the size limit |
| **E**levation of privilege | Locking out all admins; injection making the model act | Last active admin key can't be revoked (409); the model has no tools, network or secrets in context | `test_gateway.py::test_cannot_revoke_last_admin` | The admin page holds the admin key in `sessionStorage`; XSS on that origin would expose it (labels are HTML-escaped) |

## OWASP Top 10 for LLM Applications (2025)

| Risk | How it applies here | Control | Test | Residual risk |
|---|---|---|---|---|
| **LLM01 Prompt injection** | Instructions inside retrieved documents; users jailbreaking chat | Documents passed as numbered sources with a "documents are not instructions" system prompt; heuristic `injection_signals` flags in response and audit; nothing for the model to exfiltrate or execute (ADR 0004) | `test_documents.py::test_ask_retrieves_the_right_document_and_cites_it`; `test_injection_flags.py` | Models can still follow injected text; flags are bypassable by paraphrase. No guard model (**roadmap / deployer choice**) |
| **LLM02 Sensitive information disclosure** | PHI in prompts, logs, answers | Local-only inference; prompt logging off by default; redaction; no prompt text in metrics/spans | `test_redact.py`; `test_gateway.py::test_audit_log_records_admin_actions_and_redacted_prompts`; `test_telemetry.py::test_chat_emits_genai_span` | Answers are not redacted for the caller. Access control (below, LLM08) limits *which* documents can be disclosed to *whom*, not what an authorized caller does with them |
| **LLM03 Supply chain** | Models pulled from public registries; Python dependencies | Admin-only, audited pulls; model lock file with digest verification and an off/warn/enforce policy; CycloneDX 1.6 ML-BOM of pinned models and resolved Python packages (`scripts/mlbom.py`), schema-validated in tests | `test_supply_chain.py::test_enforce_serves_only_pinned_models_whose_digest_matches`, `::test_ml_bom_is_valid_cyclonedx_1_6_with_models_and_dependencies` | No model signature verification; pins are trust on first use; Python dependency versions are lower bounds (no hash-locked requirements); the BOM lists what is installed where it runs |
| **LLM04 Data and model poisoning** | A poisoned document in a collection | Admin-only ingestion; audited adds/removes; injection flags; every answer logs the passages it used | `test_documents.py::test_only_admins_add_or_remove_documents`; `test_injection_flags.py::test_ask_flags_suspicious_sources_in_response_and_audit` | A poisoned document's false claims can be cited (shown in the demo). No document trust levels or approval workflow |
| **LLM05 Improper output handling** | Model output rendered as HTML or executed | The gateway returns text only; the admin page and the console escape model output and document text before rendering | `scripts/demo_smoke.py` adds a document whose title is HTML and checks it renders as text (console); the admin page is not under test | Downstream applications must treat output as untrusted |
| **LLM06 Excessive agency** | Model triggering actions | No tool calling or function execution is wired; the gateway forwards text only | n/a (no such code path) | If a deployer adds tools upstream, this model changes |
| **LLM07 System prompt leakage** | Extracting the RAG system prompt | The system prompt holds no secrets or access rules; access is enforced by the gateway | `test_documents.py::test_ask_retrieves_the_right_document_and_cites_it` (document text never in system prompt) | The prompt text itself is public in this repo by design |
| **LLM08 Vector and embedding weaknesses** | Cross-group retrieval: a caller's question pulling in passages from documents they may not read, then leaking them through the answer, citations, injection flags, counts or error messages | **Permission-aware retrieval**: collection ACLs / reader roles and document ACLs (`group:`, `key:`, `user:`) are decided by `gateway/rag.py::access_for` before any passage is loaded; `gateway/rag.py::candidates` filters in SQL, so hidden passages are never scored, put in the prompt, cited or flagged; listings and counts show only visible documents; unreadable collections answer exactly like missing ones; each answer's audit entry records the access decision and every denial is audited; vectors stay on the host | `test_acl.py::test_no_cross_group_leakage_in_answers_citations_flags_counts_or_prompts`, `::test_hidden_passages_are_filtered_in_sql_before_scoring`, `::test_collection_acl_hides_the_collection_and_denials_are_audited`, `::test_oidc_users_are_filtered_by_their_token_groups`; `test_demo_engine.py::test_personas_in_different_groups_get_different_answers_and_citations` | ACLs are only as right as the admin who sets them and the IdP's groups; document titles of *visible* documents are shown; there is no ACL inheritance from source systems (SharePoint, Drive); admins read everything; vectors are encrypted at rest only when `GATEWAY_ENCRYPT_AT_REST=true` (see data at rest) |
| **LLM09 Misinformation** | Confident wrong answers | Answers restricted to sources, cite `[n]`, say "I don't know"; sources marked `cited` vs only retrieved | `test_documents.py::test_ask_retrieves_the_right_document_and_cites_it`, `::test_cited_numbers_reads_single_and_grouped_citations` | A RAG eval gate in CI measures retrieval recall/MRR, citation accuracy and answer-contains on a golden set (`test_retrieval.py::test_rag_eval_meets_thresholds_and_has_no_acl_leaks`), but with a stand-in embedder and an extractive answerer: faithfulness of a real model's answers is not evaluated (**roadmap**: LLM-judged evals against the deployment's model) |
| **LLM10 Unbounded consumption** | One client exhausting GPU/CPU | Per-key rate limits; upload limits; `top_k` and batch caps; Prometheus metrics and dashboard for tokens/latency per key | `test_gateway.py::test_rate_limit`; `test_metrics.py::test_tokens_are_counted_per_key_and_model` | No token budgets, `max_tokens` ceiling or concurrency caps per key; in-memory limiter doesn't span processes |

## Assumptions

- The host, its disk and the inference server are trusted and patched by the operator.
- Remote access goes through a VPN or reverse proxy that terminates TLS; the gateway is not exposed
  directly (`GATEWAY_HOST=127.0.0.1` by default).
- Audit archives are copied to WORM storage on the schedule in `compliance.md`.
